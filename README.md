# 追因 · 智能代码根因定位台

> 把业务异常变成开发可以复核的代码线索。

追因是一份可在本机运行的根因定位演示版。产品经理或业务同学写下异常现象、预期结果和复现步骤，系统随后只读扫描已经授权的 Python 代码目录，给出最多三个值得优先检查的代码位置。

每个候选都带有文件行号、源码证据、业务到代码的因果链、修复建议和验证方式。开发不必从整个项目盲目搜索，可以从证据较集中的位置开始复核。

## 它解决什么问题

业务反馈通常描述用户看到了什么，代码排查需要知道状态在哪条路径里出了问题。两种语言之间隔着调用关系、数据状态和项目上下文。

追因负责完成第一轮翻译。它读取有限范围内的源码，把业务现象交给代码分析模型，再用后端规则校验模型给出的路径和行号。页面展示的是排查候选，最终判断仍由开发结合日志、测试和真实环境完成。

## 一次排查怎样进行

1. 启动服务时指定允许读取的 Python 目录。未指定时使用仓库内置的优惠券示例。
2. 在页面填写异常现象，可补充预期结果和复现步骤。
3. 确认自己有权分析该目录，并同意把本次所需的源码片段提交给模型服务。
4. 后端在授权目录内扫描源码，并调用本机已经登录的 Codex 命令行工具。
5. 页面返回最多三个根因候选。第一项默认展开，其余项目按需查看。
6. 下载候选报告，交给开发继续确认和修复。

## 内置演示

仓库附带一个小型订单与优惠券项目。演示问题来自取消订单流程。订单取消以后，优惠券仍保持已使用状态，用户再次下单时无法使用同一张券。

首页点击“填入优惠券示例”即可回填业务工单。这个案例包含处理器、订单服务、优惠券服务、数据仓储和一条预期失败的业务测试，足够展示跨文件定位过程。

## 当前输出

- 一段面向业务和开发的结论摘要
- 最多三个候选代码位置
- 经过后端重新提取的真实源码行
- 业务现象到错误状态的因果链
- 修复建议与验证方式
- 扫描文件、服务耗时和本次限制
- 可下载的 Markdown 候选报告

## 工作原理

```text
业务异常与源码授权
        ↓
本地工作台
        ↓
输入校验与仓库路径锁定
        ↓
只读扫描 Python 文件并添加行号
        ↓
Codex 返回结构化候选
        ↓
后端校验路径和行号并重建源码证据
        ↓
最多三个可复核候选与本次限制
```

前端集中在一个原生 HTML 文件中。`server.py` 使用 Python 标准库提供页面和接口，`analyzer.py` 负责扫描、模型调用与结果校验。整个项目无需前端构建步骤。

## 安全边界

追因只读取启动时授权的目录。浏览器不能修改仓库路径，目标项目也不会被写入。

分析器只收集 `.py` 文件，不执行目标项目代码、测试或 Git 命令。单个进程同时只接收一项分析任务，避免重复调用。

模型运行在只读模式和临时工作目录中。后端会丢弃越出授权目录的路径、无效行号和无法对应到真实源码的证据。页面在用户明确勾选授权以前不会提交分析请求。

源码片段会发送给本机 Codex 登录所对应的模型服务。请只分析自己有权提交的代码。

## 运行条件

- Python 3.9 或更高版本
- 已安装并登录 Codex 命令行工具
- 一个允许读取的 Python 代码目录
- 首页视频需要网络连接，核心排查页面仍由本地服务提供

本项目没有第三方 Python 依赖。

## 快速开始

macOS 用户可以双击 `启动追因.command`。

终端启动方式如下。

```bash
python3 server.py
```

浏览器会打开下面的本地地址。

```text
http://127.0.0.1:8765
```

分析自己的项目时，在启动命令里传入绝对路径。

```bash
python3 server.py --repo "/你的/Python/项目路径"
```

如果只想离线演示页面和结果结构，可以强制使用内置规则模式。该模式不会调用模型，输出会明确标记为演示结果。

```bash
CHECKPOINT_SCRIPTED_FALLBACK=force python3 server.py
```

## 项目结构


## 扫描限制

当前版本最多读取 80 个 Python 文件。单个文件最多读取 80,000 字节，总上下文最多保留约 220,000 个代码字符。隐藏目录、虚拟环境、依赖目录、符号链接和缓存目录会被跳过。

这些限制让本地演示保持可控。超出范围的文件不会悄悄进入模型上下文，页面会在报告限制中说明截断情况。

## 接口

```text
GET  /api/health
GET  /api/config
POST /api/analyze
```

分析请求使用下面的 JSON 字段。

```json
{
  "bug_report": "异常现象",
  "expected_result": "预期结果",
  "reproduction_steps": "复现步骤",
  "source_consent": true
}
```

`bug_report` 和 `source_consent` 为必填项。服务端拒绝字符串形式的假授权，也会拒绝超出长度限制的输入。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

现有六项单元测试覆盖只读扫描范围、无效路径和行号过滤、真实源码证据重建、明确授权，以及并发分析拒绝。测试使用模拟结果，不会发起真实模型调用。

`sample_repo/test_cancellation.py` 用来还原优惠券问题，里面保留了一条预期失败的业务断言。它不属于上面的产品测试套件，请不要把全仓库 `pytest` 的失败误认为追因自身测试失败。

## 当前边界

当前版本面向本机单用户和 Python 项目。它没有接入运行日志，不会执行目标项目测试，也不会自动修改代码。报告提供排查起点，候选仍可能存在误报或遗漏。
